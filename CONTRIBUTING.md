# Contributing to Search Lens

Thank you for your interest in contributing to Search Lens.

Search Lens is built around a simple idea:

Technology should help users understand information, not make decisions for them.

This document explains the principles and guidelines for contributing to the project.

---

# Project Philosophy

Before contributing, please understand the main principles of Search Lens:

## Transparency over blocking

Search Lens is not designed as a simple advertising blocker.

The goal is to analyze, classify and explain search results.

Removing or hiding content is only one possible user choice.

---

## User control

Search Lens should never force a single way of viewing search results.

Users decide:

- what they want to highlight;
- what they want to hide;
- what information they want to see.

---

## Minimal intervention

Changes should affect the presentation of information, not break websites or interfere with their normal operation.

---

# Types of Contributions

Contributions can include:

- code improvements;
- new detection methods;
- search provider support;
- documentation improvements;
- bug reports;
- testing;
- user experience suggestions;
- translations.

---

# Feature Requests

Before suggesting a new feature, consider:

- Does it improve transparency?
- Does it give users more control?
- Does it fit the philosophy of Search Lens?

Features that only create aggressive blocking behavior may not fit the project's goals.

---

# Code Contributions

When contributing code:

- keep changes focused and understandable;
- avoid unnecessary complexity;
- document important decisions;
- consider future maintainability;
- respect existing architecture.

The project values clear and reliable solutions over quick but fragile implementations.

---

# Detection Rules

Detection logic is an important part of Search Lens.

New detectors and rules should:

- have a clear purpose;
- explain what signals they analyze;
- avoid false positives when possible;
- be easy to update.

A detection rule should explain why a result was classified.

---

# Documentation

Good documentation is an important part of the project.

Documentation should be:

- clear;
- accurate;
- easy to understand;
- available in English when possible.

Russian translations and other languages are welcome.

---

# Community Guidelines

Contributors should:

- communicate respectfully;
- discuss ideas openly;
- accept constructive feedback;
- focus on improving the project.

Different opinions are welcome. The goal is to build a useful and transparent tool.

---

# Final Principle

Search Lens should always follow one rule:

Help users see more clearly. Do not decide for them.
