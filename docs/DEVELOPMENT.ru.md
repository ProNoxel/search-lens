# Руководство по разработке

## Обзор

Этот документ описывает процесс разработки и техническое окружение Search Lens.

Цель этого руководства — помочь участникам проекта подготовить рабочее окружение и понимать принципы работы над проектом.

---

# Текущий статус разработки

В настоящее время Search Lens находится на этапе формирования основы и подготовки прототипа.

Основные направления работы:

- создание структуры браузерного расширения;
- реализация анализа результатов поиска;
- разработка системы обнаружения;
- создание функций визуализации с контролем пользователя.

---

# Технологический стек

Начальный стек разработки:

- Browser Extension API (Manifest V3);
- TypeScript;
- современные веб-технологии;
- модульная архитектура.

Конкретные инструменты разработки могут изменяться по мере роста проекта.

---

# Среда разработки

Для участия в разработке Search Lens потребуются:

- современный браузер с поддержкой расширений;
- Git;
- Node.js и менеджер пакетов;
- редактор кода.

Рекомендуемые инструменты:

- Visual Studio Code;
- Chrome или другой браузер на основе Chromium.

---

# Структура проекта

Проект разделён на отдельные области:

- документация;
- исходный код расширения;
- основная логика системы;
- поисковые провайдеры;
- модули обнаружения;
- пользовательский интерфейс.

Структура может изменяться по мере развития проекта.

---

# Принципы разработки

## Фокус на изменениях

Каждое изменение должно решать конкретную задачу и оставаться понятным для проверки.

---

## Следование архитектуре

Новые функции должны соответствовать существующей модульной структуре.

Логика поисковых провайдеров, логика обнаружения и интерфейс должны оставаться разделёнными.

---

## Объяснение решений

Важные технические решения должны документироваться.

Будущие участники должны понимать не только то, что было изменено, но и почему.

---

## Приоритет поддержки проекта

Понятный и читаемый код важнее коротких, но сложных решений.

---

# Тестирование

Тестирование станет важной частью разработки Search Lens.

Будущие тесты должны проверять:

- точность обнаружения;
- совместимость с поисковыми системами;
- поведение пользовательского интерфейса;
- предотвращение ложных срабатываний.

---

# Процесс участия в разработке

Типичный процесс внесения изменений:

1. Создать или выбрать задачу.
2. Обсудить предлагаемое изменение при необходимости.
3. Реализовать изменение.
4. Проверить результат.
5. Отправить изменение на рассмотрение.

---

# Текущая цель разработки

Первый прототип должен продемонстрировать:

- работающее браузерное расширение;
- обнаружение рекламных элементов в результатах поиска;
- режим выделения под контролем пользователя.

---

# Главный принцип

Разработка Search Lens должна следовать той же идее, что и сам продукт:

Создавать прозрачные инструменты, которые дают пользователям больше контроля.
