# Участие в разработке Search Lens

Спасибо за интерес к участию в развитии Search Lens.

Search Lens построен вокруг простой идеи:

Технологии должны помогать пользователям понимать информацию, а не принимать решения за них.

Этот документ описывает принципы и правила участия в проекте.

---

# Философия проекта

Перед участием в разработке важно понимать основные принципы Search Lens.

## Прозрачность вместо блокировки

Search Lens создаётся не как обычный блокировщик рекламы.

Главная цель проекта — анализировать, классифицировать и объяснять результаты поиска.

Удаление или скрытие контента является только одним из возможных вариантов выбора пользователя.

---

## Контроль пользователя

Search Lens не должен навязывать единственный способ просмотра поисковой выдачи.

Пользователь самостоятельно решает:

- что он хочет выделить;
- что он хочет скрыть;
- какую информацию он хочет видеть.

---

## Минимальное вмешательство

Изменения должны влиять только на представление информации, не ломая сайты и не нарушая их обычную работу.

---

# Виды вклада в проект

Вклад в проект может включать:

- улучшение кода;
- создание новых методов обнаружения;
- поддержку новых поисковых систем;
- улучшение документации;
- сообщения об ошибках;
- тестирование;
- предложения по улучшению интерфейса;
- переводы.

---

# Предложения новых функций

Перед предложением новой функции стоит проверить:

- Повышает ли она прозрачность?
- Даёт ли она пользователю больше контроля?
- Соответствует ли она философии Search Lens?

Функции, направленные только на агрессивную блокировку, могут не соответствовать целям проекта.

---

# Вклад в код

При добавлении кода:

- делайте изменения понятными и сфокусированными;
- избегайте лишней сложности;
- документируйте важные решения;
- учитывайте дальнейшее развитие проекта;
- соблюдайте существующую архитектуру.

Проект отдаёт предпочтение понятным и надёжным решениям, а не быстрым, но хрупким.

---

# Правила обнаружения

Логика обнаружения является важной частью Search Lens.

Новые анализаторы и правила должны:

- иметь понятную цель;
- объяснять, какие признаки они анализируют;
- по возможности избегать ложных срабатываний;
- быть удобными для обновления.

Каждое правило обнаружения должно объяснять, почему результат получил определённую классификацию.

---

# Документация

Качественная документация является важной частью проекта.

Документация должна быть:

- понятной;
- точной;
- удобной для изучения;
- по возможности доступной на английском языке.

Русские переводы и другие языковые версии приветствуются.

---

# Правила сообщества

Участники проекта должны:

- общаться уважительно;
- открыто обсуждать идеи;
- принимать конструктивную обратную связь;
- сосредотачиваться на улучшении проекта.

Разные мнения приветствуются. Общая цель — создать полезный и прозрачный инструмент.

---

# Главный принцип

Search Lens всегда должен следовать одному правилу:

Помогать пользователям видеть яснее. Не решать за них.
