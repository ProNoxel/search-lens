# Архитектура Search Lens

## Обзор

Search Lens разработан как модульная система для анализа, классификации и настройки отображения результатов поиска.

Главная архитектурная цель — отделить логику конкретных поисковых систем от основной системы анализа.

Это позволяет Search Lens поддерживать несколько поисковых платформ, сохраняя единый и расширяемый движок.

# Ядро системы

Ядро системы является центральной частью Search Lens.

Оно не содержит логики, привязанной к конкретной поисковой системе.

Основные задачи:

- обработка результатов поиска;
- сбор аналитических признаков;
- запуск модулей обнаружения;
- расчёт уровня уверенности;
- назначение категорий результатам.

---

# Поисковые провайдеры

Поисковые провайдеры содержат логику, связанную с конкретными поисковыми системами.

    providers/

       yandex/

       google/

       bing/

Каждый провайдер отвечает за:

- поиск контейнеров результатов;
- извлечение URL;
- извлечение заголовков и описаний;
- понимание структуры страницы.

Слой провайдеров не должен решать, является ли результат рекламным, органическим или относится к другой категории.

Его задача — только предоставить структурированные данные для дальнейшего анализа.

---

# Система обнаружения

Система обнаружения анализирует отдельные результаты поиска.

Возможные анализаторы:

- анализатор меток;
- анализатор ссылок;
- анализатор редиректов;
- анализатор параметров отслеживания;
- анализатор текста;
- анализатор структуры страницы.

Каждый анализатор изучает определённые признаки и передаёт информацию в движок классификации.

Пример:

     Обнаружена метка "Реклама"
          +100 баллов

     Обнаружен рекламный редирек
          +80 баллов

     Обнаружены параметры отслеживания
          +30 баллов

     Общий результат: 210 баллов

---

# Движок классификации

Движок классификации преобразует обнаруженные признаки в категорию результата.

Пример:

      Категория:
      Реклама

      Уверенность:
      98%
      
Другой пример:

      Категория:
      Органический результат

      Уверенность:
      95%

Решения классификации должны быть объяснимыми.

Пользователь должен понимать, почему результат получил определённую категорию.

---

# Слой отображения

Слой отображения отвечает за то, как классифицированные результаты показываются пользователю.

Возможные режимы:

- оригинальный вид;
- выделение;
- уменьшение заметности;
- сворачивание;
- скрытие.

Система классификации и система отображения должны оставаться независимыми.

Search Lens определяет тип результата.

Пользователь решает, как этот результат будет отображаться.

---

# Пользовательский интерфейс

Пользовательский интерфейс предоставляет контроль над поведением Search Lens.

Возможные настройки:

- режим отображения;
- включённые категории;
- пользовательские правила;
- настройки приватности;
- инструменты разработчика.

---

# Система правил

Правила определяют дополнительную логику обнаружения.

Пример структуры:

    rules/

       yandex/

       google/

       community/

Правила должны быть:

- понятными;
- редактируемыми;
- расширяемыми;
- удобными для участия сообщества.

---

# Принципы проектирования

## Модульность

Компоненты должны быть независимыми и заменяемыми.

## Прозрачность

Каждая классификация должна иметь понятное объяснение.

## Минимальное вмешательство

Search Lens должен изменять представление информации, не нарушая работу сайтов.

## Расширяемость

Добавление нового поискового провайдера или нового анализатора не должно требовать переписывания всей системы.

## Контроль пользователя

Search Lens предоставляет возможности выбора.

Окончательное решение всегда остаётся за пользователем.
